# Music Website Manager

Tools for uploading your MP3s to Hugging Face and rebuilding the song data
used by the **विविध जिनवाणी संग्रह** player.

The player lives at the repo root (`index.html`, `script.js`, `style.css`) and
reads its data from `data/`. This folder holds the helper scripts that keep
that data in sync with your media.

Live player: https://dhanyakumarjain.github.io/vividh-jinvani-sangrah/

## How It Works

```
media/                <- your songs (this is a clone of the Hugging Face dataset)
  Morning Prayers/    <- each subfolder becomes one playlist
    song1.mp3
  Evening Aarti/
    song2.mp3

data/
  songs.json          <- generated by STEP-2 (or TOOL-Sync-Local)
  playlists.json      <- generated by STEP-2 (or TOOL-Sync-Local)
  config.json         <- player config; lastUpdated timestamp is refreshed
```

- `media/` is **gitignored** in the main project - it is its own Git repo that
  points at the Hugging Face dataset `dhanyakumarjain/temp`.
- The player streams songs directly from Hugging Face, so uploaded files are
  immediately playable once `data/` is updated.
- File names ending with a single `✽` are ALSO collected into the playlist
  `0000 सुपर जैन भक्ति संग्रह` (in addition to their own folder).

## Prerequisites

1. **Git** - https://git-scm.com/download/win
2. **Git LFS** - https://git-lfs.github.com/ (or `winget install GitHub.GitLFS`)
3. **Python 3** - https://www.python.org/downloads/ (check "Add Python to PATH")

Hugging Face authentication (first push only):

```bash
git config --global credential.helper manager
```

When prompted, use your HF username and an Access Token from
https://huggingface.co/settings/tokens (Write access).

## Scripts

| Script | Purpose |
|--------|---------|
| `START-HERE.bat` | Menu driven guide to everything below |
| `SETUP-Check-System.bat` | Check Git / Git LFS / Python / auth are ready |
| `SETUP-First-Time.bat` | Clone the Hugging Face dataset into `media/` (run once) |
| `SETUP-Fix-Problems.bat` | Reset a broken Git configuration |
| `SETUP-Large-Files.bat` | Configure Git LFS to track media file types |
| `STEP-1-Upload-Songs.bat` | Force-push `media/` to Hugging Face |
| `STEP-2-Update-Website.bat` | Fetch songs from Hugging Face, rebuild `data/` |
| `STEP-3-Publish-Website.bat` | Commit and push the website to GitHub Pages |
| `TOOL-Sync-Local.bat` | Rebuild `data/` from the local `media/` folder (offline) |
| `TOOL-Test-Website.bat` | Run the site locally at http://localhost:8080 |
| `TOOL-Reset-Data.bat` | Clear `media/` and empty `data/` (local only, dangerous) |

Python helpers live in `python/`:
`sync-media.py`, `sync-local-media.py`, `fetch_songs.py`, `reset-data.py`,
`generate-git-info.py`.

## Common Workflows

### First time on a computer

```bash
cd mp3-management
SETUP-Check-System.bat     # verify requirements
SETUP-First-Time.bat       # clone media/ from Hugging Face
START-HERE.bat             # main menu
```

### Add or update songs

```bash
# 1. Put MP3s in media/ (organize into subfolders = playlists)
# 2. Upload to Hugging Face
cd mp3-management
STEP-1-Upload-Songs.bat
# 3. Rebuild the website data (from Hugging Face)
STEP-2-Update-Website.bat
# 4. (optional) preview locally
TOOL-Test-Website.bat
# 5. Publish
STEP-3-Publish-Website.bat
```

### Work offline (no Hugging Face)

Put files directly in `media/` and run `TOOL-Sync-Local.bat`. This rebuilds
`data/songs.json` and `data/playlists.json` from the files on disk. Note that
the player streams from Hugging Face, so you still need to upload (STEP-1)
before those songs play for everyone.

### Sync from another machine

```bash
cd media
git pull origin main
cd ../mp3-management
TOOL-Sync-Local.bat        # or STEP-2-Update-Website.bat
```

### Start completely fresh

```bash
TOOL-Reset-Data.bat         # empties media/ and data/ (local only)
# add new files to media/, then:
STEP-1-Upload-Songs.bat
STEP-2-Update-Website.bat
STEP-3-Publish-Website.bat
```

## Folder = Playlist

Every subfolder inside `media/` becomes one playlist. To rename or reorder a
playlist, rename or reorder the folder and re-run `TOOL-Sync-Local.bat`.

User-created playlists (made inside the player) are stored in the browser's
`localStorage` (`mp2_playlists`) and are not part of `data/`.

## Troubleshooting

**"Git / Python / Git LFS is not recognized"**
Install the missing tool and restart your terminal. Run
`SETUP-Check-System.bat` to re-check.

**Push rejected / authentication failed**
Use an Access Token, not your account password. Re-run
`SETUP-Fix-Problems.bat` if Git config is corrupted.

**Website does not update after publishing**
GitHub Pages can take 1-2 minutes. Refresh with Ctrl+F5.

**Songs do not play**
Confirm the files are supported audio formats and that folder/file names do
not contain unusual characters.

## Notes

- `media/` is the single source of truth for uploaded songs and is gitignored
  by the main project (`hf-dataset/` is deprecated).
- STEP-1 uses **force push** - your local `media/` overwrites the remote.
- The player defaults to the blue theme; appearance is a player-side setting,
  not a data setting.
